# Fiche de collaboration support ou client

## État actuel

Au 3 août 2026, le dépôt GitHub RoundLab ne contient aucune issue, aucune revue
de pull request et aucun commentaire provenant d'un tiers identifiable. Aucun
cas de support externe complet n'est donc encore disponible.

Cette fiche doit être remplie avec un échange réel. Le développeur ne doit pas
jouer artificiellement le rôle du client et du support.

## Cas à documenter

| Champ | Valeur |
| --- | --- |
| Identifiant de l'issue | À compléter |
| Date du signalement | À compléter |
| Interlocuteur et rôle | À compléter avec son accord |
| Canal | GitHub Issue, entretien, e-mail ou autre |
| Problème initial | À compléter |
| Impact utilisateur | À compléter |
| Version et environnement | À compléter |
| Correctif livré | À compléter |
| Version ou commit | À compléter |
| Confirmation de résolution | À compléter |

## Trame de l'échange

### 1. Retour initial du client ou du support

Conserver une citation courte ou une reformulation validée, la date et le lien
ou la capture. Masquer les données personnelles inutiles.

### 2. Reformulation technique

Expliquer le problème sans jargon, son périmètre et ce qui reste inconnu.

### 3. Questions et reproduction

- action exacte qui déclenche le défaut ;
- fréquence ;
- navigateur et système ;
- résultat attendu ;
- données minimales partageables ;
- logs ou capture sans information sensible.

### 4. Répartition des contributions

| Partie | Contribution réelle |
| --- | --- |
| Client ou utilisateur | scénario, contexte et validation du résultat |
| Support, si présent | qualification, impact et communication |
| Développeur | diagnostic, correctif, tests et livraison |

### 5. Explication du correctif

Décrire la cause, le changement et ses limites dans des termes compréhensibles
pour l'interlocuteur.

### 6. Validation finale

Joindre la réponse explicite confirmant que le défaut est résolu ou expliquer
pourquoi la validation reste en attente.

## Preuves à annexer

- [ ] signalement original daté ;
- [ ] questions de clarification ;
- [ ] étapes reproductibles ;
- [ ] lien vers le correctif et ses tests ;
- [ ] preuve de déploiement ;
- [ ] retour du client ou du support après correction ;
- [ ] anonymisation et autorisation de présentation vérifiées.
